# ES6

## 输入网址到首屏画面呈现

第一阶段：网络链路与资源请求（获取 HTML）

这是浏览器“空手道”开始前的准备动作，耗时主要取决于网络状况。

DNS 解析：浏览器将域名（如 example.com）转换为服务器的 IP 地址。

TCP 连接：通过三次握手建立与服务器的 TCP 连接（HTTP/2 和 HTTP/3 有优化）。

TLS 协商（HTTPS）：进行加密协议握手，确保安全通道建立。

发送 HTTP 请求：浏览器向服务器发送 GET 请求，等待服务器返回响应头及 HTML 文档的字节流。

第二阶段：构建 DOM 和 CSSOM（解析文档）

浏览器开始“阅读”拿到的 HTML 和 CSS 数据，但此时屏幕上依然一片空白。

字节流解码：将收到的二进制字节流解码为字符，再根据 HTML 规范词法分析成 Token（标签），最终构建出 DOM 树（文档对象模型）。

构建 CSSOM（关键渲染路径阻塞）：解析 HTML 时，遇到 `<link>` 或 `<style>` 标签会立即去请求或解析 CSS。CSS 不会阻塞 DOM 的构建，但会阻塞页面的渲染，因为浏览器需要完整的 CSSOM 树才能决定元素长什么样。

预加载扫描器：在主解析器解析 HTML 的同时，浏览器会启动一个“预加载扫描器”，它会提前发现 img、script、css 等资源链接，并并行提前下载它们，避免串行等待。

第三阶段：渲染树生成与布局（计算位置）

现在有了 DOM（结构）和 CSSOM（样式），浏览器开始“排版”。

合并为渲染树（Render Tree）：从 DOM 根节点开始遍历，过滤掉 display: none 等不可见元素，结合 CSSOM 为每个可见节点计算出最终的样式（即样式计算）。

布局（Layout / Reflow）：计算每个可见节点在视口（Viewport）内的精确几何位置（坐标和尺寸）。这一步非常耗费性能，它会遍历整个渲染树。

第四阶段：首次绘制（Painting）—— 首屏出现

这是用户第一次看到画面的时刻，通常对应性能指标 FP（First Paint） 或 FCP（First Contentful Paint，首次内容绘制）。

绘制（Paint）：将布局后的元素，按照层级（层叠上下文）划分成多个绘制图层（Layer）。

栅格化（Rasterization）：将绘制指令交给 GPU 进程，把图层切分成图块（Tile），并栅格化为屏幕上的像素点。

合成（Composite）：GPU 将多个图层按照顺序合成在一起，最终显示在屏幕上。此时你可能看到背景色、文字或首屏的基本骨架。

第五阶段：脚本执行与资源加载（填充与交互）

首屏虽然显示了，但页面通常还没“活”起来。

JavaScript 的“阻塞”效应：`<script>` 标签（未加 async/defer）会暂停 DOM 解析，立即下载并执行 JS。此时如果 JS 操作了 DOM，会触发强制回流（Reflow）或重绘（Repaint），导致首屏时间延后。

加载关键媒体资源：首屏内的 img、字体文件（@font-face）正在下载，下载完成后触发重新布局和绘制，这时用户会看到图片闪现或文字变化。

LCP（最大内容绘制）：首屏内最大的元素（通常是图片或大块文字）渲染完成，标志着首屏主要内容加载完毕。

### 页面加载较慢，问题主要在这几点

| CSS 阻塞渲染 | 构建 CSSOM 完成前，浏览器不会渲染任何东西。| 提取首屏关键 CSS（Critical CSS）内联到 `<head>`；非关键 CSS 异步加载。|

| JS 阻塞解析 | 普通 `<script>` 会阻止 DOM 构建，拖慢整个流程。 | 使用 `<script defer>`（DOM 解析完后执行）或 `<script async>`（下载完立即执行，不阻塞）。|

| 图片/字体延迟 | 未设置尺寸的图片或字体请求会触发布局抖动（Layout Shift）。| 图片添加 width/height 或 aspect-ratio；字体使用 font-display: swap。|

## 白屏问题

### 经典白屏（FCP延迟/FP未触发）

现象：浏览器地址栏转圈，页面完全空白，没有任何文字、背景色或占位图，持续数秒甚至数十秒

原因：

CSS 阻塞：浏览器必须构建完整的 CSSOM 才能绘制页面。如果 `<head>` 中有巨大的外部 CSS 文件未加载完，或者 CSS 文件被严重压缩且网络慢，浏览器会“宁愿不画”，导致白屏。

JS 阻塞：浏览器在构建 DOM 时遇到普通的 `<script>` 标签（无 async/defer），会暂停 DOM 构建去下载并执行 JS。如果这个 JS 特别大（如 2MB 的库文件）或执行耗时（如死循环），DOM 树无法继续构建，渲染无法触发。

解决方案：

内联关键 CSS（Critical CSS）：将首屏必需的样式（布局、背景色）直接用 `<style>` 标签内联在 `<head>` 中，让浏览器无需等待外部文件即可立即绘制。

外部 CSS 异步加载：非首屏 CSS 加上 media="print" 或使用 preload + onload 异步加载，避免阻塞。

JS 添加 defer / async：非必须的 JS 加上 defer（DOM解析完后执行）或 async（下载完立即执行且不阻塞），把“阻塞执行”变成“并行下载”。

服务端渲染（SSR）：对于 React/Vue 单页应用（SPA），使用 SSR 直接返回填充好内容的 HTML，客户端无需等待 JS 下载执行就能看到骨架。

### SPA（单页应用）框架特有的“加载白屏”

现象：页面先极快地闪现了一下背景色或 Loading 图标，然后突然变成白屏，或者一直白屏直到几秒后所有内容突然蹦出来。

根本原因：JS 加载或执行报错导致“水合（Hydration）”或“挂载（Mount）”失败。

解决方案：

添加骨架屏（Skeleton Screen）：在 HTML 内联 CSS 中直接绘制一块灰色的占位布局（如文章轮廓、头像占位）。这样即使 JS 没加载完，用户看到的也是“有结构的灰块”，而非空白。

资源加载失败兜底：给 `<script>` 标签添加 onerror 重试机制，或利用 Service Worker 缓存备用 JS。

前端错误监控与容错：使用 window.onerror 或 try-catch 捕获渲染期错误；在 Vue 中使用 errorCaptured 钩子，React 中使用 Error Boundaries（错误边界），防止单个组件报错导致整页白屏。

路由懒加载 + 预加载：使用 webpack 的代码分割，首屏只加载核心 JS，并利用 `<link rel="preload">` 提前加载首屏路由的 JS 模块。

### 接口异常与数据依赖导致的白屏

现象：页面样式、骨架屏都显示正常，但数据区域空白，或者整个页面被一个透明的遮罩层挡住。

根本原因：首屏强依赖的接口报错或超时。

解决方案：

默认数据（Default Props）：在请求数据前，先给组件赋予默认的空数组或空对象，确保 v-for 或 map 不会因 undefined 而报错。

合理设置超时与重试：接口请求设置 3-5 秒超时，超时后自动重试一次，或直接降级展示“加载失败”提示，而不是死等白屏。

加装 Loading 遮罩但不阻挡点击：如果是 SPA 的路由切换，可以使用 keep-alive 或延迟加载动画，避免路由切换时整个视图被清空导致的白屏闪烁。

终极排查工具（如果遇到线上白屏）

看network面板，是否有js、css资源不是200，如果有 404 或 403，说明资源部署路径错误（常见于打包后静态资源路径 publicPath 配置不对）。

看 Console（控制台）：是否有醒目的红色报错信息（如 Uncaught TypeError）？如果有，定位到报错行数（Source 面板）即可修复。

看 Sources（源代码） 的 Coverage 工具：查看首屏下载的代码中，有多少是当前未执行的，评估是否有不必要的庞大依赖。

## 防抖

防抖（Debounce）：像电梯关门。如果有人不断走进来（持续触发），电梯门就永远不关；直到最后一个人进来后过了 N 秒没人再来，门才关上运行（执行一次）。

标准实现（带immediate选项）

```js
function debounce<T extends (...args:any[]) => any>(
    func:T,
    delay:number,
    immediate:boolean = false
):((...args: Parameters<T>) => void) & { cancel: () => void } {
    let timer: ReturnType<typeof setTimeout> | null = null;
    const debounced = function (this: ThisParameterType<T>, ...args: Parameters<T>) {
        const context = this;
        // 如果 immediate 为 true 且 timer 为空，说明是第一次触发，立即执行
        if (immediate && timer === null) {
            func.apply(context, args);
        }

        // 清除上一次的定时器
        if (timer) clearTimeout(timer);

        // 重新设定延迟执行
        timer = setTimeout(() => {
            if (!immediate) {
                func.apply(context, args);
            }
            timer = null; // 重置，使得下一次触发能再次立即执行
        }, delay);
    };

    // 添加取消方法，用于组件卸载时清除定时器，防止内存泄漏
    debounced.cancel = () => {
        if (timer) {
            clearTimeout(timer);
            timer = null;
        }
    };

    return debounced;
}
```

## 节流

节流（Throttle）：像水龙头滴水。不管你怎么猛转把手（疯狂触发），水珠都只能每隔 N 秒滴下一滴（固定频率执行）。

```js
function throttle<T extends (...args: any[]) => any>(
  func: T,
  limit: number
): ((...args: Parameters<T>) => void) & { cancel: () => void } {
  let lastCall = 0;
  let timer: ReturnType<typeof setTimeout> | null = null;

  const throttled = function (this: ThisParameterType<T>, ...args: Parameters<T>) {
    const now = Date.now();
    const remaining = limit - (now - lastCall);

    if (remaining <= 0) {
      // 如果距离上次执行超过了时间间隔，立即执行
      if (timer) {
        clearTimeout(timer);
        timer = null;
      }
      lastCall = now;
      func.apply(this, args);
    } else if (!timer) {
      // 如果还没到时间，设置一个定时器，确保最后一次触发也能执行
      timer = setTimeout(() => {
        lastCall = Date.now();
        timer = null;
        func.apply(this, args);
      }, remaining);
    }
  };

  throttled.cancel = () => {
    if (timer) {
      clearTimeout(timer);
      timer = null;
    }
  };

  return throttled;
}
```

| 维度 | 防抖（Debounce）| 节流（Throttle）|
| 执行时机 | 延迟执行：连续触发时，只执行最后一次（或第一次）。 | 限频执行：固定时间间隔内，只执行一次。|
| 最终效果 | 将多次高频操作合并为一次。 | 将多次高频操作稀释为低频。|
| 适用场景 | 搜索框输入联想、窗口 resize 停止后的重绘、表单验证。 | 滚动加载（scroll）、鼠标拖拽、游戏动画帧、上传进度。|
| 比喻 | 电梯关门 | 红绿灯（固定放行）|

## 深拷贝

深拷贝：创建一个新对象，并递归复制原对象所有层级的属性/元素，使新对象与原对象完全独立。修改副本不会影响原对象。

推荐：structuredClone

const copy = structuredClone(obj);

JSON序列化

const copy = JSON.parse(JSON.stringify(obj));

问题：会丢失 undefined、函数、Symbol；Date 变字符串；NaN/Infinity 变 null；Map/Set 变 {}；循环引用报错。

function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj;
  if (map.has(obj)) return map.get(obj);

  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj.source, obj.flags);

  if (obj instanceof Map) {
    const copy = new Map();
    map.set(obj, copy);
    obj.forEach((v, k) => copy.set(deepClone(k, map), deepClone(v, map)));
    return copy;
  }

  if (obj instanceof Set) {
    const copy = new Set();
    map.set(obj, copy);
    obj.forEach(v => copy.add(deepClone(v, map)));
    return copy;
  }

  const copy = Array.isArray(obj) ? [] : Object.create(Object.getPrototypeOf(obj));
  map.set(obj, copy);

  for (const key of Object.keys(obj)) {
    copy[key] = deepClone(obj[key], map);
  }
  return copy;
}

## 垃圾回收

可达性分析，从根对象开始，沿着引用链遍历。能到达的对象保留，到不了的回收。

JS 用可达性分析判断对象存活，V8 通过分代回收、Scavenge、标记-清除/整理、增量并发标记等策略，在自动释放内存的同时尽量降低停顿。避免内存泄漏的关键是：及时解除引用、清理监听和定时器、用 WeakMap/WeakSet 做弱引用缓存。
